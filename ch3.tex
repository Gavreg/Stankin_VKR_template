Работа оформляется 14 кеглем. В \LaTeX{} для каждого кегля вручную забит его физический размер, и для 14 он составляет 14.4 пт\footnotemark  (все вопросы к Дональду Кнуту).

\footnotetext {В Microsoft Word один пункт равен 1/72 дюйма (так называемый PostScript-пункт или bp), в то время как классический пункт в LaTeX (pt системы TeX) равен 1/72.27 дюйма. Размер шрифта  в дюймах в \LaTeX{} $1/72.27\cdot14,4 \sim 0,1993$ будет примерно равен размеру в Word $1/27 \cdot 14 \sim 0,1944$ }

\myfontsize{} пт это высота прямоугольника, в которой вписаны все символы шрифта --- кегельной площадки. Во времена печатных станков именно на таких площадках располагались все буквы. Ее высота и называется кеглем шрифта (а не размер букв, как многие полагают). Часть площадки заходит под базовую линию, создавая глубину шрифта, именно в ней располагаются хвостики букв у, р, ц, щ, и т.\,д. Для Times New Roman глубина составляет 443/2048 кегля. Остальная часть площадки, (1825/2048) определяет высоту букв над базовой линией.

Межстрочный интервал в работе равен полтора. В \LaTeX{} форма определения межстрочного интервала следующая:
\begin{equation}
	I = X B,
\end{equation}
$X$ --- коэф. масштабирования, хранится в макросе \Verb|\baselinestretch|, а $B$~--- жёстко заданный для каждого кегля в классе документа базовый интервал.  Получим его значение (см. код) --- %
{% изолирем все изменения в группе
	\def\baselinestretch{1}% ставим множитель по умолчанию - 1
	\selectfont% применяем шрифт, отрабатывает формула I = 1*B
	\xdef\tmpbaselineskip{\fpeval{\baselineskip}}% Записываем длину получившуюся длину
}%  
\tmpbaselineskip{} пт. %Выводим ее.
На основании этого определяем коэф. $X$, чтобы межстрочный интервал получился 24.225 пт (именно такое расстояние между строками в Word при полуторном интервале и 14 кегле):
\begin{equation}
	24.225 / 17 = 1.425.
\end{equation}
Именно это значение задано в преамбуле командой \Verb|\def\baselinestretch{1.425}|.

\subsection{Списки}


\subsubsection{Маркированные и нумерованные списки}


Нумерованный список необходимо использовать тогда, когда важно передать порядок перечеслителей. В остальных случаях используется ненумерованный (маркированный). Примеры в этом разделе не несут смысловой нагрузки и демонстрируют только варианты оформления.

Все списки подчиняются правилам русского языка и являются предложениями. После точки предложение заканчивается, а новое начинается с большой буквы.

Например, включенный в строку нумерованный список может выгладить следующим образом: помидоры бывают разные: 1) чёрные; 2) белые; 3) красные. В этом случае, писать каждый элемент списка с Большой буквы было бы не корректно. Пример этого же списка в выключенном виде: помидоры бывают разные:
\begin{enumerate}[label = \arabic*)]
	\item \tikz[remember picture,overlay]{\draw [red, ->] (\fpeval{-\itemindent}pt,0.5ex) -- ++(-1.25cm,0) node [midway, above, font=\tiny] {1.25см};}%
			чёрные; 
	\item белые; 
	\item красные.
\end{enumerate}




Когда вам необходимо в пункты списка включать целые предложения, то следует поступать следующим образом. Помидоры  бывают разных видов:

\begin{enumerate}
	\item Помидоры бывают чёрные.
	\item Помидоры бывают белые.
	\item Помидоры бывают красные.
\end{enumerate}


Ненумерованные списки используют если порядок перечисляемых объектов не важен. Пример:

\begin{itemize}
	\item пункт 1;
	\item пункт 2;
	\item пункт 3;
\end{itemize}

Пример списка:
\begin{enumerate}[label = \arabic*)]

	\item белые;

	\begin{enumerate}[label = {\asbuk*)} ]

		красно-жёлтые;
		\item красно-белые;
		\item красно-зелёные:
		\begin{itemize}
			\item красно-зелёные в полосочку;
			\item красно-зелёные в клеточку;
		\end{itemize}

\end{enumerate}

Или так:
\begin{enumerate}[]

	\item Яблоки бывают жёлтые.
	\item Яблоки бывают красные. Выделяют три типа красных яблок:
	\begin{enumerate}[label*={\arabic*.} ]
		\item Красно-жёлтые яблоки.
		\item Красно-белые яблоки.
		\item Красно-зелёные яблоки.
	\end{enumerate}
\end{enumerate}

Формулы оформляются в выключенном виде\footnote{В контексте оформления научных текстов бывают внутритекстовые (включенные в абзац) и выключенные (вынесенные в отдельную строку) формулы.}. Для формул обязательна нумерация --- следует использовать математические окружения, которые её поддерживают (см. документацию по пакету amsmath). Следующий абзац  демонстрирует корректный пример использования формулы в тексте.

Концептуальная модель $n$-ой предметной задачи определяется следующим образом:
\begin{equation}\label{eq:KM}
	K\!P2(n) = \left< M2(n0, T\!H2(n), \overline{F\!U2}(n), R^{K\!P}_2(n) \right>,
\end{equation}
где $M2(n)\equiv A(n)$~--- множество предметных категорий, $T\!H2(n)$~--- множество динамических отношений на $A(n)$, $T\!H2(n)$~--- множество статических отношений на предметных категориях, $ \overline{F\!U2}(n)$~--- множество динамических ограничений на взаимосвязь предметных категорий, $ R^{KP}_2(n)$~--- отношения между статический и динамической составляющими концептуальной модели.

На формулу в последующем тексте можно ссылаться: а поняли ли вы, что обозначает формула \eqref{eq:KM}?

\subsection{Рисунки}

Рисунки добавляются в работу в виде плавающих объектов\footnote{Плавающие объекты --- объекты которые будут расположены не там, где описаны в коде, а где \LaTeX{} решит их разместить.}. 

В шаблоне настроен следующий порядок размещения всех плавающих объектов (т.е. рисунков, таблиц и листингов)~--- !htb. Это значит: h (here)~--- разместить объект там, где он расположен в коде. Если не получится (например, страница закончилась)) использовать t (top)!--- верх следующей страницы, если не получится~--- b (bottom)~--- низ  страницы.

Рисунки должны быть расположены после первой ссылки на них на текущей или на следующей за ней станице. Располагать рисунки дальше не рекомендуется (пожалейте читателя). Пример ссылки:  рисунок \ref{fig:stankin_first_website} показывает как по данным Wayback Machine первый сайт МГТУ <<СТАНКИН>> в 1998 году. Ссылку можно оформить еще так: по данным Wayback Machine сайт МГТУ <<СТАНКИН>> в 1998 году (рис. \ref{fig:stankin_first_website}).

\subsection{Листинги}

Располагаются аналогично рисункам и таблицам. В листинге \ref{lst:listingexample} показан пример. Допускается цветная разметка синтаксиса, но если вы собираетесь печатать работу в чёрно-белом варианте, ее лучше не использовать, или использовать контрастные цвета. 

\begin{listing}
	\caption{Пример}
	\label{lst:listingexample}
	\begin{minted}[autogobble]{cpp}
		
		// 1. Объявление лямбда-выражения и сохранение его в переменную sum
		auto sum = [](int a, int b) 
		{
			return a + b;
		};		
		// 2. Вызов лямбда-выражения
		int result = sum(5, 3);
		std::cout << "Результат: " << result << std::endl; // Выведет 8	
	
	\end{minted}
\end{listing}

Короткие листинги лучше размещать в плавающих объектах в тексте работы, Длинные, которые занимают больше листа, следует выносить в приложение (приложение \ref{sec:appB}).
